# Decisions and why

| Decision                                                                                                                                               | Why                                                                                                                                                 |
| ------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| Pivot from a sub-agent directory to a desktop orchestrator (2 Oct)                                                                                     | The owner wants to show agent harness, orchestration and evals skills for AI-company roles; a working app shows more than a directory               |
| Keep the repo name and all history; old app at tag `directory-v1`                                                                                      | GitHub contribution graph                                                                                                                           |
| Electron + TypeScript, pnpm monorepo                                                                                                                   | One language end to end; a native-feeling Mac app with full Node access for git and CLIs                                                            |
| No backend; local SQLite; bring your own Claude plan                                                                                                   | Free to run, nothing to host, code never leaves the Mac; a backend only for future team features                                                    |
| Claude Code first, Codex next, own harness kept                                                                                                        | Most users already pay for Claude; the built-in harness (Anthropic API, `claude-opus-5`) shows the harness skills                                   |
| Every run on its own git worktree and branch                                                                                                           | Agents never touch your working copy; many runs in parallel; easy to discard                                                                        |
| The project's checks decide "done", failures sent back (max 2)                                                                                         | Proof instead of the agent's word                                                                                                                   |
| Lean Claude Code workers (no MCP/plugins/skills)                                                                                                       | A simple question once cost ~200k tokens from the user's setup; slash runs opt back in                                                              |
| One event stream for every agent                                                                                                                       | Activity, traces, errors work the same whatever agent ran                                                                                           |
| Black/white themes, Geist, orange for action only                                                                                                      | Owner's taste; calmer than gradients                                                                                                                |
| Live demo = the real UI on a mock API                                                                                                                  | Website shows the actual product, always in sync, no real data                                                                                      |
| Agent runs git itself (commit/pull/push/merge); risky ones go through approvals, no blanket allowlist; `helloagents` command for shipping and new runs | The owner wants agents to commit and push on request; going through the app keeps it visible and reuses tested Ship code (was: agent never commits) |
| Push opens a PR by default; Merge into main pushes main                                                                                                | The owner found "where is my code" confusing; one clear default and a pill that matches GitHub                                                      |
| Remove run folders after push/PR/merge, keep branches                                                                                                  | 3 runs used 1.2 GB (mostly node_modules); the owner chose the simple rule                                                                           |
| Approvals via `--permission-prompts host --permission-prompt-tool stdio`                                                                               | Same channel as Anthropic's Agent SDK; works headless; enables mode switches and plans                                                              |
| Auto mode by default                                                                                                                                   | The owner wants to automate tasks; Claude Code's own auto mode still asks about risky actions                                                       |
| Keep stdin open for the whole run                                                                                                                      | Needed for approvals, background commands, mid-task messages and mode switches                                                                      |
| Fix check environments automatically                                                                                                                   | A broken tool isn't a code problem; the agent shouldn't be asked to fix it                                                                          |
| Non-git folders added directly (git set up locally)                                                                                                    | The owner wanted no extra step; worktrees need git                                                                                                  |
| Mac only, ad-hoc signed, not notarized                                                                                                                 | Notarization needs a paid Apple developer account; later                                                                                            |
| One release command that also updates the website                                                                                                      | The owner wants the landing page always on the newest version                                                                                       |

Reversed (8 Oct, v0.2.25): runs no longer start lean. The owner wants every Claude Code
capability ("it SHOULD BE ABLE TO DO ALL THE CLAUDE CODE OPERATIONS"), which outweighs
the token savings.
